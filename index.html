Autonomous Story Production Pipeline

Built

A fully autonomous agentic workflow that turned a single prompt into a finished illustrated learning film for my kids, in the spirit of Bluey and Blippi. A crew of specialized agents each held one job: a story hunter to source the idea, an author to write it, and others down the chain. Each handed off to the next with no human in the loop. The pipeline called out to ElevenLabs for narration and a separate service for image and video generation, and an episode came out the far end on its own.

It taught me more about agent design than anything else I've built: role separation beats one enormous prompt, and the handoff contract between agents matters more than any individual agent's instructions.

Shared AI Skill Library

Active

An Obsidian vault that works as shared memory for the coding agents I use. Skill and workflow notes sit behind a single index, and Claude Code and Codex are both told to start there and load only the one note that matches the task, never the whole vault. A sync script keeps the reference copies in step with the runtime source, and a written policy says which notes are generated and which are maintained by hand.

It exists because agents forget everything between sessions. Context that is cheap to recover is worth more than a longer prompt, and a library nobody prunes turns into noise the model has to read around.

Proxmox Home Lab

Active

A virtualized fleet for testing infrastructure changes, running containerized services, and breaking things safely before they matter. Most of what is on this page runs here. High-availability thinking at a scale I can afford to blow up, which is exactly why it's where I learn the things production won't let me.

It is a single Proxmox node, so the operations work is the interesting part: nightly guest backups, encrypted offsite copies to object storage, a restore I have actually tested, uptime checks, and alerts to Discord for disk space, SSD wear, and failed backups.

Distributed Monitoring & Automation Platform

Active

A multi-agent system that watches a live online marketplace for state changes and reacts within seconds. A central hub API coordinates distributed watcher agents running across the Proxmox fleet, with client-side plugins reporting telemetry back and a shared database reconciling what each agent believes it saw. Watching was the easy part. The hard part was designing for agents that disagree, and for a data source that lies by omission.

Deliberately vague: the domain and mechanism are confidential. The architecture is the interesting part anyway.

About Me

From dial-up to high availability.

I grew up in Jefferson County, Missouri, and for most of my childhood the plan was sports: basketball, baseball, football, whichever one was in season.

That changed in sixth grade, when a Compaq Presario showed up in the house. It ran on dial-up, so one phone call could drop the connection and take the afternoon with it. I spent a lot of time working out why things had stopped working, and I have been doing some version of that ever since.

I knew I wanted to work in IT, but my first job was as an administrative assistant for Jefferson County government. There was no on-site IT, so anything with a plug on it ended up with me: the phones, the printers, the county website. Nobody else was coming to fix it, so I learned fast.

That experience got me into Ricoh in 2015 as a support analyst, without a degree, and I stayed nine years. I moved into channel account management, where I learned discovery, requirements gathering, and how to explain a complex system to someone who doesn't work in it. After a year as an IT service specialist I moved into technology design, building proof-of-concept environments and solution designs for large enterprise clients.

School happened around full-time work the whole way. I have worked full time since I was eighteen, finished my associate's in 2016, and finished my bachelor's in 2020. Most of what I studied, I had already had to solve on the job.

In June 2024 I joined Primary Systems to do hands-on engineering. I started as an IT Systems Engineer I, moved to II in 2025, and to III in August 2026. I work on high-availability infrastructure for clinical environments: virtualization, SQL Server Always On availability groups, identity, integrations, and monitoring. The stakes are easy to see in healthcare. When a system goes quiet, a nurse call doesn't route.

At home I run a lab where I test ideas before they go anywhere that matters and build tools I actually use, mostly with AI coding tools like Claude Code and Codex.

The common thread is that I don't much care whether a problem is technically mine. Someone has to find the answer, and I would rather it be me.

Outside of work: two kids, a home lab that is always one project deeper than planned, and an unreasonable amount of emotional investment in Mizzou and the Cardinals.
